    Case catalogue: every workflow, and every case of it¶

    This is the list of what a person can do in openball and what can go wrong while they do it, for six kinds of people: the anonymous visitor, the player, the group organiser, the team captain (and member), the venue owner and the platform admin. Each case is one thing worth checking, with what should happen, and how it is checked.

    How to read the last column:

    • Automated: X1 the case is walked by a journey of the evidence walkthrough (the journey tests). The journey has its own page with pictures: journeys/. It is run in a real browser, on a fresh local stack, and the recorded run is in the docs.
    • Written before #606 was merged. Organised open games and the team name/crest edit (pull request #606) were not on main when these journeys (E1, E2) were written, so they were written against the branch, run green on a stack built from it, and made to skip themselves with a reason on a build without the feature (they ask the running app). #606 has since been merged, so they now run as part of every full run.
    • Finding the case is walked by a journey, and the journey ends in a product problem that is filed as a GitHub issue (linked in the row). The step is recorded as failing in the run on purpose; the case counts as automated in the totals. These labels describe main today (some of those issues are being fixed in other pull requests).
    • Not automatable here and why. These cases are still worth a person's eyes; the reason says what is missing (a real bank, a real inbox, a physical phone, a week of waiting) and, where there is one, which other test proves the rule.

    Every journey runs in Greek (the default), and the cases about language also in English. "Light and dark" and "phone width (390 px)" pictures are taken in the same journey where the case is about them.

    Totals are at the end of this page (Counts).

    2. Signing in and out (L, R)¶

    Sign-in is a six-digit code sent to an e-mail address (no passwords). How tests log in is explained in journeys/LOGIN.md: there is no test backdoor in the product.
